## ⚙️ 2. Zero-Cost Infrastructure & Scaling Blueprint

To reach 1 Million users with **$0 budget**, we optimize free tiers across cloud providers:

```
┌─────────────────────────────────────────────────────────────┐
│                       Client App (React Native / Expo)      │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTPS / Firebase SDK
        ┌──────────────────────┴──────────────────────┐
        ▼                                             ▼
┌──────────────────────────────┐       ┌──────────────────────────────┐
│  Firebase Spark Plan         │       │  GitHub Actions / Cron       │
│  - Firestore (1 GiB free)    │       │  - Runs daily build script   │
│  - Firebase Auth (Unlimited) │       │  - Calls Groq API (Free)     │
│  - Hosting (< 10 GB free)    │       │  - Calls Edge-TTS (Free)     │
└──────────────┬───────────────┘       └──────────────┬───────────────┘
               │                                      │
               └──────────────────┬───────────────────┘
                                  ▼
                   ┌──────────────────────────────┐
                   │  Firebase Hosting CDN        │
                   │  - Serves MP3 Audio (.mp3)   │
                   │  - Serves Cover Art (.jpg)   │
                   └──────────────────────────────┘
```

### Free Tier Limits & Mitigation at Scale
1. **Cloud Firestore (1 GiB free storage & 50K reads / 20K writes per day)**:
   - *Mitigation*: Cache daily stories locally using AsyncStorage. Implement pagination and efficient indexing so users only fetch what they view.
2. **Firebase Hosting / CDN (10 GB storage, 10 GB/day transfer)**:
   - *Mitigation*: Audio files (`.mp3`) are lightweight (~1-2MB per 5-minute story). At 1M users, hosting large audio directly on Firebase Hosting bandwidth could exceed limits. 
   - *Zero-Cost Solution*: Offload audio storage to **Internet Archive (archive.org)** or **GitHub Releases / LFS**, or use decentralized CDN caching via Cloudflare Free Tier in front of Firebase Hosting.
3. **Groq API & Edge-TTS**:
   - *Mitigation*: Daily automated GitHub Actions cron job generates exactly 2-4 stories per day and caches them permanently. Client requests do not hit LLMs directly; they read pre-generated static content from Firestore & CDN, resulting in **zero LLM rate-limit issues at scale**.

## ⚠️ 5. Disadvantages, Risks & Mitigations

| Risk / Disadvantage | Impact | Mitigation Strategy |
|---|---|---|
| **Firebase Bandwidth Limits on Free Tier** | High traffic could exceed Firebase Hosting 10GB/day download limit. | Route all audio and image assets through Cloudflare Free Tier CDN caching. |
| **TTS Voice Quality Limitations** | Free TTS engines can sound robotic compared to paid ElevenLabs. | Use advanced Neural voices (`edge-tts`) with custom pitch and rate tuning (`-18%` for sleep stories). |
| **User Retention Drop-off** | Users listen once and churn. | Implement push notification reminders, daily listening streaks, and interactive branching stories. |
| **AI Generation Failures** | LLM API rate limits or downtime. | Pre-generate stories 24 hours in advance via GitHub Actions cron; maintain a rolling 10-story backup buffer in Firestore. |
